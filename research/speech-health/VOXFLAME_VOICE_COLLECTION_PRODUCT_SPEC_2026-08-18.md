# 燃言语音采集产品化标准与硬件建议

> 版本：v1.0（产品化修订稿）  
> 日期：2026-08-18  
> 基线：`燃言_构音障碍普通话语音采集标准化SOP_v1.0.docx`

## 交付目标

把“现场采集 SOP”收敛成 Web、Android、iOS 都能执行的一条最短路径：用户知道为什么录、每次只做一个动作、可以暂停/回放/撤回，数据管理员能够从一条音频追溯到说话人、场次、材料、设备、同意范围和质量结果。

本方案服务的是“让系统更准确理解真实表达”，不是普通话考试，也不要求志愿者为了“读标准”重录构音错误。

## 一、统一采集流程

### 采集前（约 2 分钟）

1. 建立匿名 `speaker_id`，确认本次用途、共享范围、退出方式和是否允许模型改进。
2. 选择采集计划：首轮基线、跨天 Anchor、连续朗读、自然表达；每次只显示当前任务。
3. 检查环境：关闭电视/音乐，手机或麦克风固定在嘴前约 20–30 cm；屏幕使用大字号单句显示。
4. 录 5 秒环境音，再读 3 个简单测试词。系统只检查“有声、不过响、没有明显断续”，不对构音做分数判断。
5. 用户确认“可以开始”。未完成前置检查时，录音按钮保持不可用。

### 采集中（每段 10–60 秒）

1. 题面只显示一个 `material_id` 和目标文本；录音 envelope 在开始时锁定，不允许录完后改题。
2. 用户可以说完即停、暂停、跳过或结束；每 3–5 分钟提示休息，出现不适立即结束。
3. 构音错误、漏读、重复、停顿、回读均保留；仅因看不清字、翻错材料、严重削波或几乎静音才建议重录。
4. 录音结束后立即显示：回放、目标文本、系统听到的文本、收音质量和“收录/不收录/重录”三个动作。上传失败先进入本机队列，不阻塞下一条。

### 采集后（约 1 分钟）

1. 随机回听 3–5 条，确认有声、无严重爆音或静音。
2. 完成 session review：材料 ID、文件完整性、元数据、原始母版、隐私和上传回执。
3. 每条样本分开保存 `prompt_text`（题面）和 `spoken_text`（实际说出）；不确定内容使用 `<UNCERTAIN>` / `<INAUDIBLE>`，不凭上下文猜写。
4. 原始母版不可覆盖；浏览器采集若本身是 PCM WAV 可直接作为母版，否则必须同时保留采集原格式母版和 16 kHz mono 训练副本。移动端 queue 保留原生录音文件，上传转换只产生训练副本。每条样本保留 checksum 和可撤回路径。

## 二、语料包与覆盖策略

### 固定材料层

| 材料 | 首轮安排 | 作用 |
| --- | --- | --- |
| `M1` 单音节固定 A 卷 | 100 字，可拆成 2–3 次 | 声母、韵母、声调和单字构音 |
| `M2` 多音节固定 A 卷 | 约 50 词，可拆分 | 连读、变调、轻声、儿化 |
| `R027` 核心朗读 | 所有人首轮同一篇，分段显示 | 跨说话人比较、连续语流 |
| `R006/R014/R031/R036/R040` 轮换朗读 | 按 speaker 轮换 1 篇 | 扩大词汇和语流覆盖 |
| `A001` 跨天 Anchor | 每次 80–120 音节 | 同人、同任务、同设备纵向比较 |
| `T001–T050` 命题说话 | 首次 60 秒，状态好再到 1–2 分钟 | 自然表达、真实词汇和语速 |

朗读作品和话题只从项目持有的合法《普通话水平测试实施纲要（2021 年版）》材料包导入。产品内保存版本号、材料 ID 和文本 hash，不在代码里复制未经授权的整篇文章。

### 语料质量门槛

- `audio_text_alignment`：材料 ID 与录音 100% 对齐；错配为 Critical，整批回查。
- `raw_master_preserved`：原始母版 100% 保留；任何格式转换不得覆盖母版，训练副本需能通过 recording ID 追溯。
- `usable_recording_ratio`：首批目标 >95%；设备问题补采，构音差异不因“说得不标准”淘汰。
- `transcript_review`：录音后可按质量问题抽查实际转写；抽查比例、阈值和停止条件必须在对应证据包中版本化，不能阻塞有效音频 + `target` 的采集。
- `speaker_split`：训练/验证/测试按 `speaker_id` 隔离，不能把同人音频拆到不同集合。
- `session_anchor_coverage`：首批目标 >90% 的说话人完成至少两次 Anchor；低于目标只标记缺失，不伪造样本。
- `inappropriate_content`：不收录与目标任务无关的广告导流、色情、直接暴力/血腥、严重 ASR 破损和可识别个人敏感信息。普通医疗求助和真实障碍表达不因敏感词误删。

## 三、统一最小元数据 contract

默认进入训练数据的字段只有：

```text
audio（原始母版）
target_text（目标文本）
spoken_text（实际转写，标注后）
severity（严重程度；不确定可留空）
etiology（病种/病因；不确定可留空）
age_band（年龄段，不收生日）
sex（性别；可选择不愿说明）
```

`recording_id`、`sentence_id`、上传状态和质量原因只作为系统追踪/质检字段，不作为模型训练特征。设备型号、采样率、声道、时长、距离仅在硬件或音频质量 A/B 需要时记录，默认不进入训练标签。用户界面不收集身份证号、详细住址、真实手机号、家属姓名或完整病历。知情同意映射表与算法数据分库存放。严重程度和病种只作为用户自报/专业人员提供的分层标签，不由一次录音自动推断。

## 四、硬件推荐与验证顺序

### P0：先用现成设备做 A/B

1. **手机内置麦克风**：作为基线，优先保证人人可用。
2. **有线 USB-C/Lightning 耳麦或近口领夹麦**：优先验证；系统识别为标准输入时无需新增 BLE 协议。
3. **蓝牙耳机/会议麦**：只作为候选，必须实测连接稳定、采样质量和延迟；不能把蓝牙芯片参数当整机效果。
4. **桌面支架、距离标记、充电宝、安静房间**：属于采集必需的现场配件。

P0 通过条件：同一批目标句、同一人、同一环境下，相对手机内置麦在系统听清、静音/削波、佩戴接受和恢复成本上有可重复净增益；否则保留手机基线，不进入定制硬件开发。

### G1：条件产品候选

挂脖/随身音频桥可作为后续候选，但必须先冻结 `input_route / output_route / control_route` 三条边界。候选器件的 SNR、AOP、续航、重量、BLE/USB 协议和报价都是待验证输入，不是已冻结 BOM。至少两家供应商用同一 RFI/RFQ 和同一 A/B 协议报价后，才进入 EVT。

### 硬件验收表

| 项目 | 通过标准 | 记录 |
| --- | --- | --- |
| 输入路由 | Web 设置页、Android、iOS 均能识别或明确回退到手机麦 | 设备型号/系统版本 |
| 位置稳定 | 20–30 cm 或近口佩戴位置可重复 | 距离/佩戴方式 |
| 音频 | WAV 母版可保存；无明显削波、断续、近静音 | sample rate/quality |
| 连接恢复 | 插拔/断连后回到安全默认设备 | 失败次数/恢复时间 |
| 用户体验 | 老年用户能独立开始、停止、回放、撤回 | 任务完成率/帮助次数 |
| 真实沟通 | 安静与轻噪声下陌生人听懂率不下降 | 同人同任务 A/B |

## 五、Web / Android / iOS 产品行为

- Web：`/contribute/topic/[topicId]` 提供采集前检查、固定材料 ID、浏览器 PCM WAV、回听和 IndexedDB 补传。
- Android：原生录音先写本机 queue，录音结束后显示质量与回放，实时转写连接失败不阻塞本地录音，网络恢复时自动上传；权限拒绝只阻断当前录音，不删除已有本机样本。
- iOS：复用同一 Expo 原生录音与上传 contract；正式可用还需 Apple 签名、真机权限、耳机路由和弱网验证。
- 三端均不把沟通页原始音频默认上传；只有明确的训练/采集同意范围才进入 dataset。
