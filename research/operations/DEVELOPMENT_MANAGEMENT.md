# 开发管理

目标：少开会、小改动、责任明确；**一个任务一个 owner，AI 产出也由人负责。**

## 1. 权限与分工

| 角色 | 负责 | 边界 |
| --- | --- | --- |
| 管理员（你） | 优先级、main 规则、迁移/发布批准、事故决策 | 日常也走 PR；生产凭证不共享给全部开发者 |
| 开发者 | 任务分支、实现、测试、PR、回退说明 | 默认代码权限和测试环境；无生产 DB/OSS 写权限 |
| 审核人 | 范围、兼容、数据安全、证据 | 非作者审核；AI 自检不等于独立人工审核 |
| 发布/值守负责人 | 对齐 Web/App/Backend、操作和观察 | 每次点名一人；小团队可兼任，但批准/执行均留名 |

入职：个人 GitHub/SSH、双因素认证、按需测试凭证；离职立即撤销组织/云/EAS/SSH/Secret 访问。生产数据不复制到个人电脑，录音测试使用授权样本；发放/回收由管理员登记。

## 2. 一个任务、一张卡、一个 PR

直接在 Issue/PR 填以下短模板，避免多套系统重复填表；复杂任务复用[执行模板](../templates/AI_EXECUTION_PLAN_TEMPLATE.md)。

```text
目的与可验收结果：
范围/不做什么/唯一事实源：
影响端与依赖/负责人/审核人/预计完成日：
最小实现/风险/监控与回退：
验证命令与结果/真机证据/缺测：
是否涉及迁移、生产、Secret或发布（需谁批准）：
```

开工先读会话摘要/当前任务/AGENTS；多人改共享文件先约定 owner 和接口，RTC 只改 Backend 契约源再生成客户端，不手改 generated。开发、测试、生产分离；没有独立测试环境时用本地隔离测试，不拿真实用户数据试迁移。

## 3. 完成标准

- **开发完成**：范围收敛，回归测试/类型/受影响构建通过，PR 审核通过，可解释失败与回退。
- **交付完成**：在需要发布时，再补部署、真实场景与观察证据。`未测 / 阻塞 / 未发布` 明确保留，不能把 mock/AI 说通过当成真机通过。
- 同步 `.claude-summary.md`、`.tasks/current.md` 与受影响手册；普通变更不改根规则流水。纯文档执行 `bash scripts/check_ai_docs.sh`，其他检查按[Harness](../aiprompts/HARNESS_ENTRY_CONTRACT.md)。

## 4. 轻量节奏（团队约定）

- 每人同时推进一个主任务；每天异步三行：完成、下一步、阻塞。审核优先，目标当天回应；超两天的分支先拆任务，不催着带病合并。
- 主干 CI 失败先修复或 revert，引入者跟进；凭证泄露/数据丢失/服务不可用立即通知管理员并停止相关发布。
- 每周 20 分钟：看未关闭风险、PR 等待、分支寿命、发布失败/恢复耗时，选一个改进项及 owner。只改流程，不按代码行数/AI 用量考核开发者。
- 单管理员阶段保留 PR/CI/自查并标明缺少独立审核；加入第二位开发者后启用非作者审核，详见[分支手册](BRANCH_MANAGEMENT.md)。

依据：[GitHub Flow/DORA](README.md#依据与采用范围)的小批量与快反馈，权限/验收边界沿[工程系统](../AI_ENGINEERING_SYSTEM.md)。这是精简团队约定，不是字节内部制度复刻。
