# Playwright 浏览器验证指南

## 目的

把 `Playwright` 作为 `VoxFlame` 的浏览器验证默认入口。

## 优先使用场景

- 页面交互
- 登录跳转
- 训练页/沟通页 UI 状态
- RTC/RTM 页面行为
- 表单流
- console 错误
- smoke / 回归验证

## 默认规则

只要问题涉及“页面应该怎么表现”，优先用 Playwright，不要先主观判断“前端应该没问题”。

## 推荐工作流

1. 打开目标页面
2. 确认关键可见文本和页面状态
3. 执行用户真正会走的交互
4. 检查：
   - URL
   - 页面文本
   - 关键按钮/状态
   - console errors
5. 再回到代码改动

## 最小记录要求

每次 Playwright 验证至少记下：

- 验证了哪个页面/流程
- 关键结果是什么
- 是否还有 console / network 异常

不要在状态文件里长期保留完整点击流水账，只保留结论。

## 适合验证的典型流程

- 首页到登录页跳转
- `/contribute` 训练页启动录音
- 沟通页点击麦克风后的录音态
- `/memory` 页面是否正确显示
- 新增 UI 改动是否真的出现在页面上

## 不要用 Playwright 代替的事情

- 纯模块级单元测试
- 不涉及浏览器状态的后端接口验证
- 纯文档改动

这些场景应优先使用更小的验证手段。
