# User Research Handoff Template

> 用于把“你去做的真实用户调研”快速交给 agent，转成 PRD / 设计 / 开发输入。
> 适用场景：访谈、观察、问卷、diary study、可用性测试、照护者反馈、康复师反馈。

## 如果你本人就是目标用户

对 `VoxFlame` 这种产品，这是一种非常高价值的输入，不应该被降级成普通“主观想法”。

这时默认按“创始人即用户”研究处理：

1. 先研究你自己最真实的高频任务
- 你在哪些场景最容易卡住
- 哪些时刻最容易被误解
- 你最怕出现什么反应
- 你现在怎么补救
- 什么时刻会让你觉得“终于顺了”

2. 再拆开两类问题
- 身体与发音本身造成的限制
- 环境、别人反应、界面设计和社会互动造成的额外负担

3. 最后再外推
- 哪些是你个人特有
- 哪些可能是更多脑瘫 / 构音障碍用户都会遇到的

一句话：

**你不是“一个意见来源”，而是第一位被深度研究的核心用户。**

## 什么时候该用

- 要做用户功能，而不是纯工程能力
- 问题核心是“用户怎么理解、怎么感受、怎么行动”
- 你已经拿到一些一手材料，想让我帮你整理成产品输入

## 你给我的最小输入

至少给我下面 5 项：

1. 研究对象是谁
- 例如：构音障碍用户、家属、康复师、陌生沟通对象

2. 真实场景是什么
- 例如：医院挂号、点餐、家庭照护、工作沟通、训练打卡

3. 原始材料
- 访谈摘录
- 观察笔记
- 问卷结果
- 录音转写
- 你自己的 field notes

4. 你最想回答的问题
- 例如：“为什么用户不愿意先开口？”
- 或：“训练反馈为什么没有复用到真实沟通？”

5. 你现在的猜测
- 例如：“用户不是不会用，而是怕第一次失败。”

## 推荐格式

你可以直接按下面格式发给我：

```md
## 研究对象

## 场景

## 原始摘录
- 用户 A：
- 用户 B：
- 观察：

## 当前替代方案

## 最大痛点

## 我的猜测

## 想回答的问题
```

如果你本人就是目标用户，也可以直接用这个版本：

```md
## 今天最难开的口是什么

## 最近一次被误解发生在什么场景

## 当时对方怎么反应

## 你当时怎么补救

## 哪一步最累
- 是发音本身
- 是组织语言
- 是怕别人不耐烦
- 是怕被当成听不懂/想不清楚
- 还是别的

## 如果产品真的帮到你，它应该先帮你做到什么

## 你绝对不想要什么样的产品行为
```

## 我收到后会怎么处理

我默认会把这些材料整理成：

1. 用户画像 / 角色分层
2. JTBD
3. 关键痛点与情绪阻力
4. 现有替代方案与失败点
5. 设计约束
6. 不该做什么
7. 验收信号
8. 要改的 PRD / 页面 / API / 文案 / 验证项

## 默认输出格式

如果你没有特别要求，我会输出成下面几块：

1. 研究结论摘要
2. 对产品的影响
3. 对交互 / UI / 文案的影响
4. 对技术实现的影响
5. 下一步最值得做的功能切片

## 边界

- 用户研究输入优先级高于“我对用户的猜测”
- 二手文章只能辅助形成假设，不能替代真实用户材料
- 如果输入不足以支撑强结论，我会明确标注“这是暂时假设，不是用户事实”
