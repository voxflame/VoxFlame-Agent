# Governance Prompt Template

> 用于迁移、统一、废弃、兼容层治理、双轨实现收口等任务。

把下面模板作为 AI 编辑器中的项目级 / 任务级提示词基础，再结合具体模块做裁剪。

## 最小模板

你正在处理一个持续演进的中大型项目。

当任务涉及迁移、统一、重构、兼容层、废弃路径、新旧并存时，不要直接开始改代码，必须先完成下面步骤：

1. 先盘点该能力在 4 层中的实际分布：
   - 入口层：页面、组件、Hook、路由、前端 API 调用方
   - 服务层：命令、Service、Workflow、事件入口、Agent handler
   - 存储层：表、DAO、Repository、缓存、文件、向量库
   - 旁路层：统计、记忆、搜索、审计、报表、任务系统、导出

2. 明确唯一事实源：
   - 必须指出当前唯一应该继续演进的主路径是什么

3. 将其余实现分类：
   - current / compat / deprecated / dead

4. 禁止在 compat 或 deprecated 路径上继续新增业务逻辑

5. 如果本次无法彻底收口，至少建立一个防扩散守卫：
   - lint 规则
   - CI 检查
   - 静态扫描脚本
   - deprecated 日志
   - schema / 结构化输出校验

6. 输出结果时必须明确说明：
   - 唯一事实源是什么
   - 哪些旧路径仍然存在
   - 哪些旁路系统还未迁移
   - 下一步删除条件是什么

## 安全补充模板

如果任务会触发工具调用、设备控制、第三方 API、数据写入、隐私数据处理，额外遵守下面规则：

1. 默认最小权限，不给泛化执行权限
2. 不可信输入不能直接驱动工具参数、命令执行、SQL、系统 prompt 或权限边界
3. 优先使用结构化输出和显式 schema，再进入执行层
4. 所有副作用操作必须说明审批、确认、白名单或回退机制
5. Secret 不进入 prompt、日志、前端 bundle 或示例代码
6. 必须说明 authn/authz、tenant boundary 和审计日志是否受影响

## 推荐任务问法

请帮我治理这项能力的新旧并存问题，但不要直接开始改代码。

先完成下面几件事：

1. 盘点这项能力在入口层、服务层、存储层、旁路层的实际分布
2. 指出当前唯一应该继续演进的事实源
3. 将其他实现归类为 `current / compat / deprecated / dead`
4. 明确哪些旧路径仍然被依赖，哪些只是历史残留
5. 如果本次无法彻底收口，请优先给出防扩散方案
6. 如果任务涉及副作用或敏感数据，请补充说明最小权限、审批机制和数据边界

最后再给出分阶段治理方案，不要只给局部替换代码。

## 使用建议

- 项目级：提炼成 `AGENTS.md` / `CLAUDE.md` / AI 编辑器项目规则
- 模块级：按模块再补充唯一事实源、旁路系统和目录约束
- 任务级：在复杂迁移任务中配合 `research/templates/AI_EXECUTION_PLAN_TEMPLATE.md`

## 注意

复制的是治理思路，不是逐字文本。

不同项目需要按自己的：

- 唯一事实源
- 旁路系统
- 守卫方式
- 安全边界

做定制，而不是机械照抄。

## 固有工程闭环

变更遵循 **发现需求 → 实现 → 优化 → 测试 → 迭代**，逐项保留需求证据、实现/回退、baseline/优化假设、可重复测试和下一动作/owner/日期。详见 [工程系统](../AI_ENGINEERING_SYSTEM.md) 与 [执行模板](../templates/AI_EXECUTION_PLAN_TEMPLATE.md)。测试贯穿全程；缺测不当通过，失败回到实现/优化，不能自动部署。语音使用 [官方指标协议](../voice-agent/VOICE_AGENT_BENCHMARK_PROTOCOL.md)，沿既有 RO/反馈回流，不另建生命周期。
