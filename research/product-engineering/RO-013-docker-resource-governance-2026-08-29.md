# RO-013 Docker 与宿主资源自动治理

## 结论

单机当前没有立即扩容证据，但必须把磁盘、构建缓存和日志治理当成持续研究对象。Docker 官方说明 `system prune` 可清理停止容器、未使用网络、悬空镜像和 build cache；命名卷默认不应随意删除。VoxFlame 采用更窄的安全策略，保护运行容器、持久化卷、`latest` 和 `pre-*` 回滚镜像。

## 生产基线

主机约 4 vCPU、7.3 GiB RAM、59 GiB 根盘；清理前 build cache 约 4.03 GiB，现已清除，运行中 5 个容器无 OOM/restart。宿主 `logs/*.log` 已配置每日轮转、50 MiB 提前轮转、保留 14 份压缩副本。业务 JSONL、录音和 OSS 数据不属于自动删除范围。

## 类似方案对照

- Docker prune：适合释放可重建对象，但 `--volumes` 风险高；不作为默认命令。
- systemd timer + 阈值：适合单机，动作可审计、可停用；不替代容量监控。
- Kubernetes/云托管：提供节点池和滚动扩展，但会增加成本与运维面，当前用户量不足以证明迁移收益。

## 分阶段计划

1. **现在**：每日 timer 检查根盘，达到 60% 执行 `prune-safe`；记录前后 Docker df、保护对象数量和日志轮转结果。
2. **稳态**：50% 告警、60% 安全清理、85% 人工升级；每周审阅增长趋势和卷使用者。
3. **扩容门**：连续 7 天 >60%、清理后仍 >60%，或实时服务因 CPU/RAM/磁盘保护阈值拒绝会话，才评估加盘/加内存/拆分 Worker。

## 失败与回退

若发现运行镜像、卷或回滚镜像被误删，立即停用 timer、保留审计日志并从备份恢复；在未完成恢复演练前不得扩大清理范围。
