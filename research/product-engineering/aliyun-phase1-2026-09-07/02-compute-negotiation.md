## 第一期3—6个月｜需求征询稿｜2026年9月7日

项目：生声不息／VoxFlame　拟签约主体：由双方核对实名认证、实际使用及发票主体后确定。

本稿供团队准备谈判及经负责人审阅后向阿里云征询；不构成采购订单、保底消费、GPU交付承诺或补贴申报。内部充值申请金额和最高预算不作为供应商报价锚点，不在本稿披露。

### 一、合作目标与采购分包

第一期拟服务约1,000名用户、采集约20,000小时语音，支持10名开发者、主站、采集站与后续多应用。自研ASR为主，阿里云ASR为有限补充和故障回退，TTS较少，LLM用于表达纠错、对话、报告和记忆整理。

已有奇绩算力支持（团队提供，尚未核对支持合同、剩余额度与到期日）。阿里云合作优先解决基础云服务、API额度、稳定连接、弹性GPU补充和后续同构扩容，而非立即替换已有支持。

| 询价包 | 范围 | 当前决策状态 |
| --- | --- | --- |
| A：基础云 | CPU、业务OSS、网络、状态服务、安全、日志与研发协作 | 优先报价，按里程碑开通 |
| B：模型API | ASR回退、少量TTS、Flash/Plus文本处理、配额与赠额 | 固定模型、地域及账单规则后小规模验证 |
| C：GPU与训练存储 | 8×RTX 5090、8×H20候选，持久存储及机房网络 | 独立报价和实测，未批准包租或采购 |
| D：政策协同 | 服务商资格、可申报SKU、费用明细与使用证明 | 阿里云提供材料，主管部门认定资格 |

**请求阿里云提供两套可比较方案：** ①沿用奇绩GPU、阿里云承接业务及必要补充；②阿里云或合规生态伙伴提供两台GPU候选。另列3个月、6个月价格和按需/包月/短租可选项，不将GPU承诺消费与基础云优惠强制捆绑。

### 二、谈判优先顺序

先确认需求与资源可交付性，再按SKU拆分报价，随后谈折扣、赠额、试用、配额和账期；最后落实政策材料与验收退出条款。优先争取可验证的低总成本和弹性，不用宣传补贴上限替代现金流安排。

本次期望获得：具名技术与商务负责人、同口径书面报价、可预约的真实任务试机、配额书面答复、逐主体账单方案和合同偏离清单。产品能力和优惠未确认时，接受标注“未提供／待确认”，不接受口头承诺代替。

## 业务容量与CPU基础资源

### 三、分清六种容量

| 维度 | 第一阶段需求口径 | 不应混淆的边界 |
| --- | --- | --- |
| 用户总量 | 约1,000名用户 | 不等于1,000名同时在线 |
| 总采集量 | 约20,000小时新增目标 | 既有约10,000小时为团队输入，来源与可训练比例待对账 |
| 平均录音并发 | 90天约28人；180天约14人 | 基于每天8小时，不含读题与休息 |
| 上传峰值场景 | 3个月80—150路；6个月40—80路 | 指突发上传压测，不能直接换算RTC路数 |
| 动态业务请求 | 总计约3,000万—5,000万次 | 90天8小时窗口平均约11.6—19.3RPS，180天约5.8—9.6RPS；峰值须实测 |
| 实时AI会话 | 单Worker既有8路完整链路证据 | 双Worker先验证16路；不能承诺80—150路RTC |

现有采集界面包含实时识别，必须检查80—150路采集时是否同样占用Agent。若每名采集者都要全程RTC，本CPU配置不能直接满足目标。建议先用预约/准入控制限制实时识别，验证录音可保存、识别可排队的方案；未经实现与验收，不把它当作现成功能。[L1—L3]

16kHz单声道16-bit音频约256kbps。150人连续产生原始音频约38.4Mbps；若150人同时把各自10秒文件在1秒内补传，则瞬时约384Mbps（均未含协议开销）。应测OSS直传和客户端补传行为，而不是给Backend购买同等音频中转带宽。

## GPU算力规划：候选需求，不提前冻结型号

### 五、两个独立GPU节点

当前约10,000小时语音为团队提供的规划基础；第一期新增20,000小时是否与其重叠须确认。仅凭音频小时数，不能推出需要两台8卡GPU，应以模型规模、训练配方、吞吐、频次、截止时间及既有支持可用量测算。

| 参数 | 节点一：训练主节点 | 节点二：吞吐/实验节点 |
| --- | --- | --- |
| GPU候选 | 8×H20，准确料号/形态待确认 | 8×RTX 5090，准确地区型号待确认 |
| 拟承担任务 | 全参数训练、大显存及长序列任务 | 微调、数据处理、批量推理、评测 |
| 主机内存目标 | 1—2TB | 512GB—1TB |
| 本地NVMe目标 | 20—30TB可用热数据空间 | 20—30TB可用热数据空间 |
| CPU与拓扑 | 按供数实测选型；列双路/NUMA及PCIe拓扑 | 明确8卡实际链路宽度、插槽与NIC/SSD争用 |
| 调度 | 与另一异构节点独立作业 | 以独立任务和数据并行为优先 |
| 当前状态 | 全部为候选需求，待书面报价/试机 | 整机可行性、供货与许可条件待确认 |

不混合两种GPU做同步训练。是否采用容器或现有任务调度工具，按团队工作流选择；10名开发者共享任务队列、配额与项目空间，不承诺10人各自独占GPU。在线自研ASR必须保留独立推理配额或实例，不能因离线训练抢占而迫使业务长期使用收费云ASR。

### 六、需要在谈判前纠正的硬件假设

1. NVIDIA公开的RTX 5090规格为单卡32GB GDDR7、无NVLink、显卡功耗575W；8卡显存算术合计256GB，不是单一连续显存池，8卡GPU功耗算术合计约4.6kW，也不是整机功耗。该原厂页面不证明中国大陆可交付型号、八卡机箱兼容、机房托管及商业许可。[N1]
2. 必须让供方明确交付5090、5090 D或其他地区/后继型号，不接受只写“5090级别”。确认制造商、显存、驱动/CUDA/训练框架兼容、P2P、散热、供电、噪声、质保及机房使用授权。无NVLink并不等于不能多卡计算，但扩展效率只能实测。
3. H20不能仅凭型号简称推定显存容量、NVLink/NVSwitch拓扑或供货日期。要求准确SKU、每卡显存、互联拓扑、出口/销售合规材料、交付机房、维护支持和可替代型号；本次未取得一手H20配置文件或书面供货承诺。
4. 若阿里云不能提供这两种裸机，不假定其公共云有对应产品。要求分别报价合法可交付的大显存训练替代与高吞吐推理替代；若涉及生态伙伴，明确签约方、发票方、SLA及数据处理责任。

**替代基线：** 先试用奇绩现有资源和1/2/4/8卡方案，再比较“专属裸机、弹性云GPU、现有支持＋高峰短租”的每个有效训练任务总成本。未完成验证，不冻结BOM或承诺长租。

## 存储、网络与总成本边界

### 七、不要把三层存储当成三份原始数据

| 层级 | 候选容量与用途 | 报价、验收要求 |
| --- | --- | --- |
| 业务数据层 | 6—10TB OSS，原录音、状态文件、标准化副本及备份 | 按平均占用、请求、下载、生命周期及恢复计费 |
| 训练持久层 | 约50TB可用逻辑空间，扩展至100TB | 可作为统一数据湖，包含上述业务数据的逻辑占用；若独立复制，另计传输与重复空间 |
| 训练热缓存 | 每台20—30TB本地NVMe，共40—60TB | 可重建缓存，不是唯一备份；区分标称容量与RAID后可用容量 |
| 可选高性能共享层 | 20—40TB，仅真实共享训练需要时开通 | 可计入50TB或作为额外性能层，两种架构分别报价，禁止默认为免费叠加 |

50TB属于训练专项，不能用基础云6—10TB预算自动覆盖。需按“原始音频＋标准化音频＋数据版本增量＋推理结果＋保留checkpoint＋备份＋余量”核定。若累计30,000小时且不重叠，PCM原音约3.456TB，50TB主要余量取决于checkpoint和版本保留策略，不由音频时长本身证明。

持久对象与训练缓存均用版本manifest/校验和管理；小文件可在训练侧按不可变版本分片，但必须追踪用户撤回到所有副本和未来训练导出。缓存可重建，未经授权不得删除原始音频；重复备份、临时盘、日志保留时间需分别设置且可审计。

### 八、区分机房内网络与云外传输

| 场景 | 规划目标 | 条件 |
| --- | --- | --- |
| 管理、SSH、监控 | 10/25GbE | 与数据平面隔离，按机房能力报价 |
| GPU到本地共享存储 | 100GbE候选基线、200GbE升级项 | 两个节点独立训练时先测25/100GbE，不把200G当无条件必需 |
| 后续同构H20跨机训练 | 400GbE RoCE/RDMA候选，GPUDirect RDMA验证 | 同构扩容和通信实测证明必要后采购；不是当前两台异构节点必需 |
| OSS到奇绩或其他机房 | 实际专线/公网路径单列 | 云内免费范围、出网、跨地域复制、专线端口与线路费逐项确认 |

上述GbE是端口/链路候选速率，不是保证到OSS或互联网的实际吞吐。要求端到端带宽、超售比、NIC数量、交换机、光模块、线缆、RDMA/RoCE适配与部署边界。不能把100/200/400GbE机房网报价误当公网带宽。

应优先在同一地域并靠近热数据调度，避免每轮训练反复出云下载。总成本比较需加入GPU闲置、存储占用、冷热恢复、重复下载、网络、安全和运维；不能只比较“元／卡时”。

## 模型API、额度和商业条款

### 九、模型API的谈判清单

| 项目 | 要求书面回答 |
| --- | --- |
| ASR | 指定当前Qwen实时型号与地域报价，计费秒数/最小粒度/静音口径；回退、对照合计按最多2,000小时做基准 |
| TTS | 指定型号及按字符/Token计价口径；固定文案缓存的许可和存储要求 |
| LLM | 分Flash/Plus、输入/输出、思考Token、长上下文阶梯、Batch/缓存与重试计价 |
| 并发 | 分ASR实时连接数、TTS并发、LLM RPM/TPM，列默认值、扩额条件、费用及生效时间 |
| 可用性 | 429/超时处理、区域异常、SLA赔付及升级支持，回退不自动解除成本限额 |
| 赠额 | 是Tokens、调用次数、Credits还是人民币抵扣金；适用SKU、领取人、有效期、消费顺序、叠加与余额查询 |
| Token Plan | 是何种订阅、是否允许生产多用户服务、是否覆盖本项目模型；专属API Key、Endpoint和迁移要求 |
| 凭证验证 | 在隔离环境用非敏感音频/文本做小额调用，检查具体账单抵扣，禁止将Key发入文档或邮件正文 |

尝试读取的Token Plan帮助地址返回HTTP 200的404内容页，不能据此确定专属Key或生产适用规则。该事项列为书面答复和试调用必答项；不提前更换线上凭证。
